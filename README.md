# Plant Atlas — 10K production data pipeline

This build converts the Plant Atlas prototype into a static, source-backed architecture designed for Cloudflare Pages/Workers Static Assets.

## Files

```text

DATA_PIPELINE.md

  level3.geojson            # generated by the importer from WGSRPD Level 3
  schema.json
  catalog/

.github/workflows/update-plant-data.yml
```

## Important: the 10,000 records are generated, not faked

Kew's current WCVP archive is 84 MB and must be downloaded from Kew when the import is run. The build environment used for this package could not embed that live archive, so this ZIP does not falsely contain 10,000 invented records.

Run the importer on a normal internet-connected machine. The Windows batch file stops at the first failed stage and always pauses at the end so you can copy the console output:

Windows:

```bat
import_10000.bat
```

macOS/Linux:

```bash
./import_10000.sh
```

After it finishes, the site will automatically switch from the demo catalog to the generated catalog because `data/catalog/index.json` will exist.

## Production data policy

- WCVP/POWO determines accepted names and native/introduced distribution.
- GBIF supplies observation identifiers and on-demand occurrence records.
- Invasive status is never inferred from "introduced" or from an observation.
- Every invasive record must carry a source URL.
- Validation fails duplicate records and malformed invasive entries.

## Cloudflare deployment

Deploy the project directory as static assets. No Node server is required by the frontend. The map's base geometry is local GeoJSON; no OpenStreetMap raster tiles are used.

## Updating data

The included GitHub Actions workflow can re-run the import and commit the generated static catalog. For large production datasets, a database/object-store backend may eventually be preferable to committing thousands of JSON shards to Git.
